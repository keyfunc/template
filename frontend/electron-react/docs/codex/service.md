# 服务模块规范

## 适用范围

- `src/service/`：按业务域组织的接口调用、参数转换与响应标准化

## 目录规范

- 服务按领域放在 `src/service/<domain>/index.ts`，领域目录使用清晰、稳定的业务名称
- 类型较多或需要跨文件共享时，在同域增加 `type.ts`；不为形式创建空类型文件
- 服务方法使用明确动词命名，例如 `getXxx`、`createXxx`、`updateXxx`

## 职责边界

- 统一通过 `@/util/request` 发起请求，不创建新的 Axios 实例
- 服务层只处理接口调用、参数转换和返回数据标准化，不承接页面展示或组件交互
- 接口原始结构尽量限制在服务层，向调用方返回明确的业务数据
- 不在服务层操作 React 状态、Zustand Store、路由跳转或 UI 提示
- 不重复实现请求基建已有的通用错误处理，也不静默吞掉异常；鉴权在业务契约明确后统一接入

请求、类型与错误细则见 [api.md](./api.md)，通用工具边界见 [util.md](./util.md)。

# 请求、类型与错误处理规范

## 请求边界

- Axios 实例统一使用 `src/util/request/index.ts` 的默认导出，业务侧通过 `@/util/request` 导入
- 页面、组件和 Store 不直接创建 Axios 实例，不重复配置基础地址、超时、请求头或通用拦截器
- 业务请求放在 `src/service/<domain>/index.ts`；服务层负责调用接口、转换参数和标准化响应
- 环境变量、第三方地址和接口常量集中维护，不把完整地址或魔法值散落在组件中

## 类型规范

- 优先复用现有类型，仅在收窄、组合、扩展语义或提升可读性时新增类型
- 请求参数可命名为 `XxxReqData`，接口响应可命名为 `XxxResData`；同一业务域保持一致
- 原始接口数据可使用 `Raw` 后缀，标准化后的数据使用明确的业务名称
- 对外类型、请求参数、响应数据及其字段补充简短中文注释，字段使用 `/** 注释内容 */`
- 类型导入使用 `import type`，避免把纯类型引入运行时代码
- 类型较少时可放在服务文件内；复杂或跨文件共享时放在同域 `type.ts`

## 数据标准化

- 响应解析、字段转换和序列化处理放在服务层或同域标准化模块
- 页面与组件只消费业务需要的数据，不重复解析接口内部结构
- 对后端字段做语义映射时保留必要注释，说明字段含义或转换原因
- 不为契约中不存在的情况添加猜测性默认值；契约不清晰时先明确类型和调用约束

## 错误处理

- 网络错误和通用 HTTP 错误由请求基建集中处理；鉴权行为在业务契约明确后再统一接入
- 服务层不重复展示通用错误提示，也不捕获后静默吞错
- 页面层只处理当前流程相关的状态，例如重试、跳转和确认交互
- 需要转换错误时保留原始原因，并提供调用方可以明确判断的错误类型或结果

服务目录约定见 [service.md](./service.md)。
